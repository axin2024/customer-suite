# 企业 CRM 与客户服务管理系统 2.0 产品需求文档

**订阅业务与客户续约运营**
需求评审版 · 2026-11-26 · 计划基线 v1.1.0（686c179）

## 产品目标与交付边界

当前发行覆盖客户商机、合同、服务工单与经营分析。本版支持以下业务流程。客户成功经理把合同转为订阅，计量用量、核对账单，再根据到期风险组织续约。 [现有项目说明](../../README.md) · [上一版业务需求](02-业务与交互-prd.md)

首期覆盖周期订阅与超量计费，付款登记由财务导入回执。发票系统通过已复核账单导出对接。

## 使用者与工作台

销售运营开通，客户管理员看权益，客服发起争议，财务复核账单，客户经理办理续约。

订阅详情并列展示签约方、服务对象、权益余额和下期预测。客服点选用量事件发起争议，财务在模拟账单比对差异后锁期，客户经理只见获授权客户。

## 状态、权限与数据

订阅 试用→有效→到期或续期，争议按账单行冻结，合同终止后仍可处理既有异议。

订阅周期采用起始含、截止不含。固定费和超量费分别舍入，冲销必须引用原用量事件。

MySQL 保存业务记录与操作回执。下列为新增逻辑对象和关键字段，所有归属组织的数据都须持有可校验的组织标识。

- `subscription(contract,term_start,term_end)`
- `entitlement(metric,limit)`
- `usage_event(source,event_id,units)`
- `amendment(effective_at,revision)`
- `renewal_case(owner,forecast)`

事件按租户、计量源、事件号唯一。账单行关联费率版本，锁期后只准新增调整行。 写入前校验操作者对目标对象的权限与当前修订。详情、搜索、导出和后台重试按同一归属校验。保留决定者、请求号、前后状态、发生时间及关联证据编号。

## 核心接口与集成

主要写入入口为 `POST /subscriptions/{id}/usage-events`。请求必填字段为 `source, event_id, occurred_at, units, metric`。成功回执提供 usage_id, billing_period, disposition。请求另带租户身份和幂等键。相同键及相同内容返回原业务编号，相同键对应不同内容返回 409。输入不满足业务约束时返回 422 和字段路径，身份无权限读取的跨租户对象返回 404。

需要异步处理时，接收事务同时写入业务记录与待处理事件，再返回 202 及回执查询地址。回读须显示当前状态、已完成步骤、上次失败原因和可重试条件。外部系统已受理但应答丢失时，按原请求身份核查实际结果。

### 合成请求与业务回执样例

请求体示例使用演练环境中的对象。带摘要的样例在开发验收时应替换为实际文件或参数的计算值。

```json
{
  "source": "S1",
  "event_id": "E82",
  "occurred_at": "2027-03-01T00:00:00Z",
  "units": 10,
  "metric": "api_calls"
}
```

业务回执示例可由提交响应或后续状态查询取得。

```json
{
  "usage_id": "U82",
  "billing_period": "2027-03",
  "disposition": "accepted"
}
```

同源 E82 改送 12 单位时返回 409，响应关联原 U82 与冲突处理号。

## 升级、部署与恢复

已签合同经确认才生成订阅，历史服务单继续按原合同查询，迁移按合同号去重。 在隔离副本运行迁移预检，输出记录数量、归属冲突和待处理编号。新增结构先部署，回填分批提交并保存游标，完成对账后按租户启用新入口。

演练时在首次成功写入新业务后中断进程，从检查点重启。核对账单重算摘要、原合同修订及计量水位。需要退出试点时停收新请求，排空已受理操作并导出未决清单。涉及数据恢复时同时恢复数据库与关联证据，再核对外部已生效的动作。

### A13 计费口径

用量先冲减配额，超量部分按每单位 2 元计费。测试者分别以客服、财务和客户账号回读原账与调整，三方须能核对同一调整编号。

## 分期交付

1. **产品权益和签约。** 交付可导入的样例和可读回的第一批业务对象，验证基础身份、归属及版本。
2. **计量及变更账务。** 串通参与角色和执行入口，演练并发、重复请求及部分成功后的恢复。
3. **争议、续约与流失复盘。** 完成全流程验收、容量实测和旧版升级。随开源发行提供中文配置、样例输入输出、备份恢复步骤及已知限制。
