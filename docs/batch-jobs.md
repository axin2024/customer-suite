# 批量任务

打开「批量任务」，选择线索分配或续约触达，勾选当前页的 1 至 50 条记录。线索分配需填写原因。填写销售人员编号分给指定人员，留空回收到公海。续约触达沿用原队列中已登记的联系人、渠道和内容。

创建后页面跳转至任务编号。工作台保存勾选次序和每条记录的原始版本。明细可回到权限范围内的原记录。提交人和本公司经理可以查看任务。市场人员办理线索，客户成功人员还需拥有对应合同的责任范围。

## 处理进程

用本公司的经理账号编号运行。可配置定时任务，例如每分钟处理 20 条。容器部署时在 `web` 容器中执行。

```sh
docker compose exec -T web php bin/crm.php batch-run 3 7 20
docker compose exec -T web php bin/crm.php batch-run 3 7 20 42
```

参数依次为公司编号、经理编号、最多处理条数和可选的任务编号。多个进程可在同一公司工作，执行器会跳过其他进程正在处理的条目。每条记录的业务写入、处理回执和任务结果一起提交。进程中断后可重复执行原命令，从仍待处理的条目继续。审计写明执行器身份和最初提交人。每次办理都重新核验提交人当前的公司岗位和对象权限。

## 处理结果与重试

| 条目状态 | 处理方式 |
| --- | --- |
| 待处理 | 等待处理器。已提交请求可按任务编号继续查询。 |
| 已完成 | 查看原记录和处理回执。可查看渠道回执编号或回放结果。 |
| 已拒绝 | 查看版本冲突、权限或授权原因。复核原记录后可另建含更新版本的任务。 |
| 可重试 | 核对渠道配置后，选择需要重试的条目。 |
| 等待外部确认 | 用原触达记录在渠道侧复核接收情况，重试仍沿用同一个渠道幂等键。 |

批量重试仅将勾选的失败条目重新排队。原选集、已完成条目及历次尝试保留。`outreach-due` 处理未纳入待处理或待重试批量任务的触达；通过普通工作台手动处理同一触达记录时仍使用同一渠道幂等键。配置外部渠道前须确认该服务能以此键识别重复请求。

JSON API 可用 `GET /api.php?resource=batches&company=3&id=42` 查询详情，或用 `resource=batch-candidates` 和 `kind` 获取可勾选记录。`batch.create` 使用原对象 `id`、`version` 作为 `items`，`batch.retry` 使用任务条目的 `id`、`version`。两个写入操作均接受现有的 CSRF 令牌和 `Idempotency-Key`。请求结果丢失时可通过 `resource=receipts` 查询原回执。
