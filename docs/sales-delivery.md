# 从报价到客户验收

## 报价和签约

1. 在商机中选定决策人，录入产品版本和价格，再推进到报价阶段。草拟报价时系统复制当时的产品明细。之后更新商机产品，旧版报价仍显示原明细。
2. 折扣使用基点，`100` 表示 1%。公司默认自行审批上限为 `1000`，经理可在「报价与审批」调整。提交时记录规则版本，超过上限须由其他审批人决定。有效日期使用 UTC，当日结束前可登记签约。
3. 已批准的报价可在原公司签约，或由集团经理按直属子公司登记分签。分签操作人须有总部和每个签约公司的经理权限。各签约客户须属于同一集团主档，每家公司一份，金额合计须与报价实收一致。
4. 在合同台账保留原始签署编号与客户主体。录入补充协议后由其他人员复核，签署后更新当前版。可从版本记录查看原合同，合并客户档案后依然能按原签约主体追溯。

系统记录线下签署凭据，供后续核对。签约金额用最小货币单位计算，折扣舍入到该单位。例如 `100.00` 的 `750` 基点折扣是 `7.50`，实收 `92.50`。

## 交接、延期和验收

1. 从已签合同的版次建立交付工作单，选定本公司的实施人员和客户代表。销售、实施分别确认同一份范围。交付开始前改范围或客户代表，双方须确认新版本。
2. 实施人员为工作单添加里程碑。登记延期时必填原计划受影响的内容和一项待客户或内部确认的事项。经理改派后，旧实施人员失去交付写权限，新人员确认后可以继续办理。
3. 完成全部里程碑并关闭待确认事项后，在工作单上录入客户确认时间和回执编号，再上传 2 MiB 内的 PDF 或 UTF-8 TXT。表单登记的是线下的客户确认，系统保留实际登记人员。验收附件与工作单绑定的旧合同版本一起归档，后续补充协议仍可独立办理。
4. 下载前复核公司与记录权限，系统同时检查文件长度和 SHA-256。回执和附件由 MySQL 同一事务写入，数据库备份应包含 `delivery_acceptances`。

自动化调用 `POST /api.php?company=<公司编号>`，带 `X-CSRF-Token` 与 `Idempotency-Key` 请求头。离线回执在 `handover.accept` 的 `file_name` 和 `file_base64` 字段上传，明确指定 `agreement_revision`。遇到连接中断，先从 `GET /api.php?resource=receipts&company=<公司编号>&key=<请求号>` 查询，再决定是否按原请求号重试。
