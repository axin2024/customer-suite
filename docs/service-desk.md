# 服务台与 SLA

经理在「服务设置」发布工作日历和 SLA，创建服务队列，并把工单分类映射到队列。服务人员需要本公司的 `service` 岗位和对应合同授权，才能接单、看详情和认领。经理可派发、回收和撤销合同授权。

一个规则版本对应一种合同服务级别，例如 `standard`。为 P1 到 P4 分别配置响应与解决的工作分钟数，解决时限不能短于响应时限。系统按来单时间选择已生效的规则，并保存规则和日历版次。

工作日历使用 IANA 时区，周一到周日是 `1` 到 `7`。每天可配置多个时间段。例外日期可设为 `[]` 表示休假，也可指定特别上班时段。

例如中国工作日从 `09:00` 到 `12:00`、`13:00` 到 `18:00`，周五 `17:50` 来单，响应目标为 30 个工作分钟。系统用掉周五最后 10 分钟，余下 20 分钟顺延到周一 `09:20`。规则启用了等待暂停时，恢复后的时限按剩余工作分钟重算。首次响应只停止响应时钟，登记解决才停止解决时钟。

合同未生效、过期、终止，或队列及规则缺失时，在「服务资格待复核」保留来单。经理补齐条件后可重新复核，服务时钟从复核通过时开始。也可说明原因后关闭，来源编号和归档记录仍可查阅。

## 外部来单和升级

把合同编号、分类、优先级和带时区的事件时间传给 `ticket.receive`。同一公司内，`source` 加 `external_id` 唯一。业务内容一致的重试返回首笔回执，换了内容则报冲突。回执包括工单编号、版本、队列、资格复核原因和时钟状态。

经理可在工作台执行超时扫描，也可由部署方调度下列命令。传入已有公司与经理编号，审计记录对应的实际执行身份。每次最多办理 100 条，重复扫描同一工单只写入一笔升级记录。

```sh
docker compose exec -T web php bin/crm.php sla-sweep 3 8
```
